# 项目目录结构评估

评估日期：2026-09-16。

## 当前结论

当前目录适合作为本地工作区。重复的根目录 `src` 已删除，`验证工具源码` 是唯一开发项目。工作区同时包含文档、原始数据、测试数据、第三方生成程序、本地缓存和试用结果；建仓前应明确哪些属于交付内容。

本次只归档任务并更新说明，不搬动其余业务文件，不初始化或发布 GitHub 仓库。

## 建仓前需要处理的问题

1. **选择仓库根目录。** 如果只交付 Java 项目，可在 `验证工具源码/` 建仓，外层文档和测试数据不会纳入。如果希望源码、需求、任务、固定测试数据一起受版本管理，建议以整个工作区为仓库根目录，保留 `验证工具源码/` 为 Maven 子目录；构建时进入该目录执行命令即可。
2. **整个工作区建仓时，需要根目录的忽略规则。** 当前 `.gitignore` 仅位于 `验证工具源码/`，不会覆盖同级 `.tools/` 和 `试用/`。应排除缓存、生成的 JAR、运行日志和报告，但保留作为测试输入的 BIN，不能简单忽略所有 `.bin` 文件。
3. **测试样例和历史备份混入生产资源目录。** `验证工具源码/src/main/resources/` 中有 XML/BIN 样例、18 个 `.bak`、1 个 `.bak2`、7 个 `.log`、5 个 `.rar` 和1个 `.zip` 文件。按当前 Maven 默认资源规则，它们会一起进入 JAR。应先识别实际运行依赖，再将固定测试样例与历史备份、生成日志分开；不能直接删除整个资源目录。
4. **XSD 位置容易误解。** `验证工具源码/test/XSD/` 实际用于程序运行时校验，且 `pom.xml` 明确从这里复制到 `dist/XSD`。它不是自动化测试目录。将来可改为 `schemas/`，但必须同步调整构建配置和引用。
5. **试用入口固定了一份程序副本。** `试用/trial.ps1` 使用本目录的 `CPM_Gen_Verify.jar`，不会自动使用最新构建的 `验证工具源码/dist` 产物；还包含本机 JDK 路径。后续宜调整为可配置 Java 路径，并调用明确版本的构建产物，避免源码更新后试用的仍是旧程序。
6. **测试数据应注明配套关系。** 根目录原始 XML、多个 BIN 数据目录和试用样例容易被误配。固定样例应说明 XML 来源、生成器版本、位数、字节序和预期结果。已有 `试用/sample/样例说明.md` 可作为格式参考。

## 建议的整理顺序

先确定仓库边界并补齐相应忽略规则；随后整理试用脚本和固定样例；最后再处理 `main/resources` 中的备份及日志、XSD 命名和重复测试目录。资源目录调整后需要重新构建并运行样例验证，避免改变现有程序查找文件的路径。

当前不用为了目录美观移动 Java 项目或重命名所有文件夹。优先确保只有一个有效源码版本、构建可复现、固定测试输入可追溯、生成文件不会误入仓库。
