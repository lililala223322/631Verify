## 离线模拟方法和边界

1. 打包来自本项目专用缓存的 Maven 插件、父 POM、传递依赖及项目依赖；未打包用户 Maven 凭据或用户 settings.xml。
2. 安装到全新目录。包内仓库不包含本项目此前安装的 `org/example/cpm-gen-verify` 构建产物。
3. 将随包的预构建 `src/dist` 移到旁边保留，确认没有 `src/target`，再从源码执行构建，排除只展示预构建 JAR 的情况。
4. 将测试进程中的系统 `JAVA_HOME`、`MAVEN_HOME` 指向不存在的位置，PATH 仅保留随包命令入口与 Windows 基础路径。实际 Java、Maven 均从安装目录调用。
5. 通过随包入口强制 Maven `--offline`，显式指定独立本地仓库、用户设置与空全局设置，并把 Java 的 `user.home` 指向安装目录下的独立位置，避免使用开发机已有 `.m2`。
6. 另给验证用 Java 进程设置安全策略，允许本地构建操作，不授予 `SocketPermission` 和 `URLPermission`。网络探针在解析 `repo.maven.apache.org` 时即被拒绝。构建和直接运行样例均在此策略下成功。

**未关闭开发电脑网卡，也未使用断网虚拟机。** 这是“独立依赖仓库 + Maven 强制离线 + Java 网络权限禁止”的模拟，不能等同于已在接收方电脑做过物理断网测试。验证用策略不改变系统防火墙；正常交付入口继续使用 Maven 离线模式，不启用已弃用的 Java Security Manager。

## 文件说明

- `verification/installed-offline-build.log`：从空构建目录重新执行构建的日志。
- `verification/installed-network-probe.log`：网络权限拒绝的探针输出。
- `verification/installed-restricted-sample.log`：禁止 Java 网络权限的样例运行输出。
- `verification/installed-launcher-sample.log`：交付样例启动脚本的运行输出。
- `verification/install-test.log`：安装和启动检查输出。
- `verification/offline.policy`、`NetworkProbe.java`：验证所用的策略与探针源码。
- `payload.sha256`：安装载荷校验值；载荷中的 `MANIFEST.json` 记录交付文件清单和逐文件 SHA-256。

探针/受限 Java 日志开头可能显示 Security Manager 的弃用警告，这是验证手段的提示，不属于 CPM 工具校验错误。

## 适用范围

本包针对当前 `cpm-gen-verify` 项目，支持通过随包环境执行 `mvn install clean`、查看版本/帮助、验证已有 XML/BIN 和运行随包样例。

没有收到 `fat-gen-verify` 的源码及 pom.xml，因此未验证 FAT，也不保证包含 FAT 或任意其他项目所需的依赖。新增或变更插件/依赖、使用不同 Maven/JDK 版本、运行其他插件目标，都需要重新验证离线依赖是否齐全。
